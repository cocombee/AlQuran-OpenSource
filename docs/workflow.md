# Narration production workflow

1. Establish the surah/ayah range, language, translation edition/version and recording/voice permissions. Record the source URL and a hash of the unchanged source text.
2. Preserve Arabic and quoted translation as canonical sources. Keep any permitted pronunciation steering or narration adaptation separate, with a change record and human approval.
3. Prepare a complete connected narration context. Split requests only at reviewed complete-context boundaries that satisfy the account's current model limits. Do not generate shared openings repeatedly when an approved recording can be reused.
4. Authorize and request one paid audition at a time. Retain request IDs, prompt hashes and output hashes. A successful request is not listening approval.
5. Select an accepted reading after listening. Keep unaccepted auditions in temporary local storage, outside production media.
6. Use local speech recognition to identify words and review context. Do not turn recognition timestamps into edit markers automatically. Verify complete word attacks/endings and actual reciter/translation pairing with waveform and human review.
7. Build or update the native timeline only after the selected source maps and takes are approved. Preserve existing manual edits, source identity, gains, effects and complete speech. Avoid gaps or source handles that expose the next verse.
8. Verify native playback, complete wording, verse pairing, tail decay and transitions. Track technical verification and final human listening approval separately.
9. Publish only the approved edition and media you have permission to distribute, with source/publisher/version information and accessible verse navigation.

Private production receipts, local paths, media library IDs and account data belong in local storage. Public issue reports should use synthetic examples or content with documented redistribution permission.
